- Alcance actual: simulador web de práctica para la certificación Professional Cloud DevOps Engineer de Google Cloud.
- Completado: harness mejorado; 15 skills, continuidad local, trazabilidad y diagnóstico disponibles; nueve pruebas de utilidades aprobadas; MVP web implementado, persistencia Redis con Docker Compose y CI configurada.
- Evidencia: ver [validación del simulador](2026-10-04-simulador-practica/validation.md) y `docs/harness-validation.md`. La documentación de uso, despliegue y operación quedó consolidada en [README.md](../README.md) y [docs/architecture.md](../docs/architecture.md). El cierre de la última pregunta ahora muestra estado de finalización, evita envíos duplicados, conserva el progreso más nuevo en el servidor y tiene timeout con error recuperable. La solicitud final envía las respuestas actuales para permitir finalizar antes del límite aunque el guardado anterior aún no haya llegado a Redis. El resultado ahora resume aciertos, errores y preguntas sin responder, y marca visualmente cada sustentación. Las lecturas independientes de sesión y binding Redis se ejecutan en paralelo para reducir latencia en Redis Cloud.
- Producto definido: práctica de preguntas, puntuación final y contexto documentado de cada respuesta para personas en preparación del examen.
- Stack definido: Next.js + TypeScript, Route Handlers, Redis con Docker Compose local y proveedor administrado compatible en producción, Vercel básico y GitHub Actions.
- Siguiente acción: completar pruebas de frontera con reloj controlado y recorrido manual en móvil para las salas. La landing pública solo permite entrar con un `roomId`; el formulario de nombre, apellidos y avatar inicia el cronómetro únicamente cuando el servidor lo acepta; el identificador de participante es interno. La entrada directa por `/room/:roomId` permanece disponible; administración, conexiones y capacitación viven en `/admin`. La landing incorpora galería comunitaria optimizada, misión, visión, pilares Aprende/Conecta/Comparte, degradado y efecto de pantalla, siguiendo el tono comunitario de [GDG Community](https://gdg.community.dev/). El despliegue en Vercel y `npm run seed:redis` contra Redis Cloud quedan después de esta funcionalidad. La sala usa el set versionado que la administración seleccionó. Se aplicaron los hallazgos de seguridad: Redis local requiere contraseña y solo escucha en localhost, las rutas globales quedaron retiradas, cada solicitud de preguntas entrega una sola pregunta, los cuerpos JSON tienen límite de 5 MB, el rate limit no confía en IPs directas manipulables y los intentos administrativos tienen protección adicional. La experiencia de examen ahora muestra guardado, navegación por preguntas, avisos progresivos de tiempo, resumen final y reintento ante errores.
- Bloqueos: el MVP funciona localmente; antes de integrar hay que resolver o aceptar explícitamente las vulnerabilidades altas transitivas de dependencias de desarrollo reportadas por `npm audit`. La auditoría de dependencias no se pudo repetir porque el entorno no resolvió `registry.npmjs.org`. La skill UI/UX individualizada pasa validaciones desde la copia completa de origen; sus cuatro tests dependientes del árbol completo no se ejecutan desde el destino aislado.
